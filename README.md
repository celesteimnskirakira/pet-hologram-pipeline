# 跟屁宠 · Pet Hologram Companion

> 让宠物的动作被看见、被记录，也继续陪伴在主人身边。

“跟屁宠”是基于**宠物健康监测项圈实时姿态识别能力**二次开发的全息陪伴项目。系统将项圈识别到的宠物动作与行为状态映射到桌面全息宠物，使主人即使不在宠物身边，也能通过一个持续同步的数字分身感知它的状态与陪伴。

本仓库提交的是黑客松期间用于快速验证全息视觉效果和现场交互流程的 **Demo 实现**。正式版的实时姿态识别、项圈数据链路和动作映射系统不在本仓库中开源。

## 为什么做“跟屁宠”

宠物健康监测项圈已经能够持续采集运动数据，并识别睡觉、趴卧、坐立、行走等姿态。我们进一步思考：

**如果这些原本只出现在健康报告里的姿态数据，也能变成一种有温度的实时陪伴，会发生什么？**

在正式产品中：

- 宠物在家睡觉，桌面的全息宠物也进入睡眠状态。
- 宠物起身活动，全息宠物同步切换相应动作。
- 项圈持续记录健康和行为数据，全息桌宠把数据转化为直观、轻量、具有情感连接的反馈。

这使健康监测从“事后查看数据”，延伸为“日常能够感受到的陪伴”。

## 正式版系统

正式版建立在已有项圈姿态识别能力之上，核心工作不在视频生成，而在于打通从真实宠物到全息分身的实时链路。

```text
宠物佩戴健康监测项圈
        ↓
传感器持续采集运动与姿态数据
        ↓
实时姿态识别与行为状态判断
        ↓
宠物身份、动作和状态映射
        ↓
全息桌宠切换对应动画
        ↓
主人看到与真实宠物同步的数字分身
```

| 系统层 | 作用 |
| --- | --- |
| 宠物健康监测项圈 | 持续采集与宠物运动、姿态相关的数据 |
| 实时姿态识别 | 将连续信号判断为睡觉、趴卧、坐立、活动等行为状态 |
| 状态同步与动作映射 | 将识别结果转成全息端动作指令，并处理动作持续、切换和异常状态 |
| 个性化宠物资产 | 保留不同宠物的外观特征，建立专属数字形象与动作资源 |
| 全息显示终端 | 接收状态并播放对应动作，让数字宠物持续呈现在桌面上 |
| 健康与陪伴体验 | 将同一份行为数据用于健康观察和情感化反馈 |

> 正式版的项圈固件、姿态识别、数据同步及实时动作映射代码目前未提交至本仓库。

## 本仓库是什么

这是“跟屁宠”在黑客松阶段的**体验验证层**，用于快速验证：

1. 用户能否从一张照片中获得“这是我家宠物”的个性化感受；
2. 黑底宠物影像在亚克力结构中能否形成自然的悬浮效果；
3. 从手机上传到现场设备播放的完整体验是否成立。

由于现场没有接入正式项圈的数据链路，Demo 使用图像与视频生成 API 制作宠物睡眠循环素材，模拟正式版收到“宠物正在睡觉”状态后的显示结果。

```text
上传宠物照片
      ↓
生成保留宠物特征的黑底形象
      ↓
生成睡眠循环视频
      ↓
合成全息显示布局
      ↓
USB 推送至 AMOLED 设备
```

**照片生成视频不是正式产品的核心技术方案，而是一条快速生成个性化演示素材的替代路径。**

## 正式版与 Demo 的区别

| 对比项 | 正式版 | 本仓库 Demo |
| --- | --- | --- |
| 动作来源 | 项圈实时识别的真实宠物姿态 | 用户选择的演示动作 |
| 内容驱动 | 连续状态数据与实时动作映射 | 预先生成的循环视频 |
| 核心目标 | 健康感知、状态同步与长期陪伴 | 验证个性化形象与全息体验 |
| 个性化方式 | 宠物数字资产及正式动作资源 | 根据单张照片生成演示素材 |
| 播放方式 | 根据宠物状态自动切换动作 | 生成后推送指定视频 |
| 本仓库是否包含 | 否，核心实现未开源 | 是 |

## Demo 已实现内容

- 提取猫狗的花色、斑纹、眼睛、耳型、白爪和项圈等外观特征
- 生成适合全息反射的纯黑背景宠物形象
- 生成低运动、可循环的宠物睡眠视频
- 检测首尾帧接缝及画面运动量
- 输出单面亚克力或四面全息锥布局
- 提供命令行、本机网页和局域网扫码入口
- 在 Mac 上完成视频转换并通过 USB 推送至 ESP32-S3 AMOLED
- 保存提示词、质量指标、任务信息和中间产物，便于复现和调试

## Demo 技术结构

```text
.

```

## 运行演示版

### 环境要求

- Python 3.10+
- FFmpeg
- Pillow
- 扫码体验台额外需要 segno 和 pyserial

macOS 安装示例：

```bash
brew install ffmpeg
python3 -m pip install Pillow segno pyserial
```

### 配置 API

```bash
cp .env.example .env
```

在 `.env` 中填写至少一个服务商 Key：

```dotenv
ARK_API_KEY=your_api_key

# 可选备用通道
# AGNES_API_KEY=your_api_key
```

`.env` 已被 Git 忽略，请勿提交真实密钥。

### 命令行

```bash
python3 cli.py doctor                 # 检查 Key、代理、网络和 FFmpeg
python3 cli.py run pet.jpg            # 运行照片生成演示流水线
python3 cli.py run pet.jpg --dry-run  # 仅估算，不调用生成 API
python3 cli.py still pet.jpg          # 仅生成黑底宠物图
python3 cli.py loop still.png         # 从已有图片生成循环视频
python3 cli.py seam video.mp4         # 检测视频接缝和运动量
```

常用参数：

| 参数 | 可选值 | 说明 |
| --- | --- | --- |
| `--provider` | `ark`、`agnes` | 演示模型服务 |
| `--pet` | `auto`、`cat`、`dog` | 宠物类型 |
| `--pose` | `curled_side`、`loaf`、`sprawl` | 演示睡姿 |
| `--resolution` | `480p`、`720p` | 视频分辨率 |
| `--ratio` | `1:1`、`16:9`、`9:16`、`4:3`、`3:4` | 视频画幅 |
| `--loop-mode` | `trim`、`xfade`、`none` | 循环接缝处理 |

### 本机网页

```bash
python3 server.py --port 8791
```

浏览器打开 `http://127.0.0.1:8791`。该服务没有公网鉴权，请勿直接暴露到互联网。

### 局域网路演模式

```bash
python3 display.py --port 8792 --lan
```

| 页面 | 用途 |
| --- | --- |
| `/u?k=...` | 访客手机上传 |
| `/` | 展台操作与任务队列 |
| `/stage` | 纯黑背景全屏展示 |

手机和电脑需要连接同一 Wi-Fi，现场建议使用私人热点。

### 独立本地体验台

`local_booth/` 将扫码、排队、生成、四面合成和 USB 推送整合为独立入口。详细说明见 [local_booth/README.md](local_booth/README.md)。

## Holo Video Uploader

`holo-video-uploader/` 提供 Apple Silicon macOS 应用，将普通视频自动处理为适配 **Waveshare ESP32-S3-Touch-AMOLED-1.75** 的格式：

```text
普通视频
  ↓
单面或四面全息布局
  ↓
360×360 / 10 FPS / MJPEG AVI
  ↓
USB 上传至 microSD
  ↓
466×466 全屏循环播放
```

详细安装、固件和后端协议见 [holo-video-uploader/README.md](holo-video-uploader/README.md)。

## 全息显示说明

项目采用 Pepper's Ghost 亚克力反射结构。黑色区域在反射中接近透明，亮色宠物主体因此呈现悬浮效果。

Demo 输出支持镜像预翻转、可选垂直翻转、近黑压暗、主体留边，以及单面和四面锥布局。不同屏幕与亚克力角度仍需真机校准。

## 说明与限制

- 本仓库用于展示黑客松 Demo，不代表正式产品的完整技术实现。
- 生成式模型存在随机性，演示前应检查预览结果。
- API 价格、模型能力和限流可能变化，批量运行前请核对服务商控制台。
- 本机网页和扫码入口为原型级工具，不应未经鉴权部署到公网。
- USB 推送要求设备运行兼容的 `UPLOAD2` 固件，同一时间只能由一个应用占用串口。
